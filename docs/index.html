How it works

You don't need to know the method.

The kit carries the method for you. Three ideas make it easy to follow, even if you have never run a requirements session or built a Power App.

1

One command per step

Ten steps, /pp:novo to /pp:publicar. Each one checks that the previous step is done. Run one out of order and it tells you which one to run instead.

2

One fresh session per step

Everything a step produces is written to disk, so the next step starts with a clean context. Every step ends with a Next step block: the command, and a reminder to type /clear first.

3

You stop only where a human is needed

Approving the MVP, the identity and the prototype; creating tables, pasting screens and flows, running acceptance and publishing. Everything else is produced and validated for you.

Lost? /pp:progresso shows where the project is and the next command, any time. The state lives in ESTADO.md at the project root.

The pipeline

Ten steps, four stages.

Open Claude Code in an empty folder and type /pp:novo followed by your idea. Then follow the Next step block at the end of each step. 🔴 human marks what only a person can do in the environment; Claude shows a numbered walkthrough and waits.

Prototype not approved

Your change requests go to ajustes-prototipo.md and the next step is /pp:design again. Mockups and prototype redo only what changed.

Tests or acceptance failed

Each failure goes to correcoes.md, tagged app or flows. The next step is /pp:construir app or /pp:construir flows, then testing again.

Stopped halfway?

Run the same command again. Steps resume from what is on disk, and /pp:progresso always knows where you are.

Brainstorm

Four ways to think, one PRD at the end.

Step 2 starts by asking how you want to think. Each mode is led by a persona and only changes how the conversation opens. All four close the same way: MVP cut, business rules, blockers, volumes and prd.md.

The agents

Specialists with the minimum tools.

Subagents can't ask you questions, so the two agents that talk with you run in the step's own session. The step that calls a subagent always re-checks its work before moving on.

Existing apps

Already have an app? Just describe the problem.

Outside the pipeline, the power-platform orchestrator routes plain requests to the right mode.

You sayWhat Claude does
“The KPI doesn't match the gallery”Investigate mode. Walks screen → formula → source → flow → procedure → data, one hypothesis at a time, and proves the root cause before proposing code.
“A user sees another unit's data”Checks the layer that actually blocks access: flow plus procedure on SQL, security roles on Dataverse. The screen only filters.
“Audit the whole app”Parallel reviewers per discipline (UX, development, performance, data, flows, SQL), then re-checks their strongest findings.
“Add a status filter here”Goes straight to powerapps-canvas, without the full protocol.
“Promote to TEST/PROD”Solutions, environment variables, connection references and pac CLI; what moves by paste versus by solution.
“Is it ready?”Runs the final gate: every applicable validator plus the checklist.

What's inside

Paste-ready parts and validators that run.

Five domain skills behind the step commands: power-platform, powerapps-canvas, power-automate, sql-procedures and dataverse.

23

Canvas components

Paste-ready YAML, with the variables each one expects in OnStart.

  • header, side menu, tabs, unit selector
  • table gallery, sorting, cursor pagination, KPI card
  • modals, loading overlay, toast, empty state, no-access panel
34

Power Automate blocks

Clipboard JSON plus notes, with the assembly order for each type of flow.

  • identify and authorize the caller, scope by unit
  • save via stored procedure, translate code and respond
  • Dataverse $batch upsert, CSV export, run log
✓

Executable validators

Python, standard library only. A ✅ needs evidence: command, output and date.

  • validar-telas.py for screens
  • verificar-fluxo.py for flows
  • lint-procedure.py, verificar-prototipo.py
One data track per project: SQL Server or Dataverse.
Real names win. Formulas and flows use the names read from the environment, never the plan.
Writes always go through a flow, with a 4-field response and .Run() inside IfError.
The flow reads the caller's identity from its own context and authorizes every action.
No environment literals in deliverables: environment variables and connection references instead.
A generator never overwrites what was pasted. Generated files go to dist/.

Install

Two commands, then /pp:novo.

Inside Claude Code, add the marketplace and install the plugin. Type /pp: to see the step commands; if they don't show up in a session that was already open, restart Claude Code.

Inside Claude Code
/plugin marketplace add <owner>/power-platform-skills
/plugin install pp@power-platform-kit
Or from a terminal
claude plugin marketplace add <owner>/power-platform-skills
claude plugin install pp@power-platform-kit
Your first app
/pp:novo an app to track orders across business units

Update later with claude plugin marketplace update power-platform-kit, then claude plugin update pp.
