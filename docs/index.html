Como funciona

Você não precisa conhecer o método.

O kit carrega o método por você. Quatro ideias deixam o caminho fácil, mesmo para quem nunca fez um levantamento de requisitos nem um Power App.

1

Um comando por etapa

Dez etapas, de /pp:novo a /pp:publicar. Cada uma confere se a anterior terminou. Rodou fora de ordem? Ela diz qual rodar no lugar.

2

Uma sessão nova por etapa

Tudo o que uma etapa produz fica gravado em disco, então a próxima começa com o contexto limpo. Toda etapa termina com o bloco Próximo passo: o comando e o lembrete de digitar /clear antes.

3

Você só para onde precisa de gente

Aprovar o MVP, a identidade e o protótipo; criar tabelas, colar telas e fluxos, homologar e publicar. O resto é produzido e validado para você.

4

Quem pensa não é quem executa

A sessão define o pedido e julga; os agentes escrevem e provam o que fizeram. Cada entrega recebe um veredito (aceito, revisão ou levada a você) antes de chegar até você.

Perdeu o fio? /pp:progresso mostra a qualquer momento onde o projeto está e o próximo comando. O estado fica no ESTADO.md, na raiz do projeto.

As etapas

Dez etapas, quatro blocos.

Abra o Claude Code numa pasta vazia e digite /pp:novo seguido da sua ideia. Depois, siga o bloco Próximo passo no fim de cada etapa. 🔴 pessoa marca o que só alguém no ambiente pode fazer; o Claude mostra um passo a passo numerado e espera.

Protótipo não aprovado

Os pedidos de ajuste vão para ajustes-prototipo.md e o próximo passo é /pp:design de novo. Mockups e protótipo refazem só o que mudou.

Teste ou homologação falhou

Cada falha vai para correcoes.md, marcada como app ou fluxos. O próximo passo é /pp:construir app ou /pp:construir flows, e depois o teste de novo.

Parou no meio?

Rode o mesmo comando de novo. A etapa retoma do que está em disco, e o /pp:progresso sempre sabe onde você está.

Depois de publicado

Mande a lista de mudanças com /pp:mudanca. Cada pedido vira um spec, os agentes fazem em paralelo, o QA roda e a homologação reabre para uma versão nova.

Os agentes

Quem pensa e quem executa

A sessão de cada etapa é a cabeça: escreve o pedido de cada agente, roda o validador de novo e dá um veredito por entrega: aceito, revisão (o mesmo agente, com um pedido mais preciso, no máximo duas) ou escalado (vem para você). Antes de mostrar a amostra do design ou o protótipo, o Claude fotografa as telas e olha. Como pensar e julgar é a parte pequena do trabalho, a cabeça pode usar um modelo mais forte e as mãos um mais rápido. Você escolhe o perfil no /pp:novo.

App que já existe

Já tem um app? É só descrever o problema.

Fora do pipeline, o orquestrador power-platform leva o pedido em linguagem natural para o modo certo.

Você dizO que o Claude faz
“O KPI não bate com a galeria”Modo investigar. Percorre tela → fórmula → fonte → fluxo → procedure → dado, uma hipótese por vez, e prova a causa raiz antes de propor código.
“Um usuário vê dados de outra unidade”Confere a camada que de fato bloqueia o acesso: fluxo + procedure no SQL, papéis de segurança no Dataverse. A tela só filtra.
“Audite o app inteiro”Revisores em paralelo por disciplina (UX, desenvolvimento, performance, dados, fluxos, SQL) e nova conferência dos achados mais fortes.
“Coloque um filtro de status aqui”Vai direto para o powerapps-canvas, sem o protocolo completo.
Uma lista de mudanças num app publicado pelo kit/pp:mudanca: um spec por pedido, agentes em paralelo, julgamento, QA da mudança e a homologação reaberta.
“Promova para HML/PRD”Soluções, variáveis de ambiente, connection references e o CLI pac; o que vai por colagem e o que vai por solução.
“Está pronto?”Roda o portão final: todos os validadores que se aplicam, mais o checklist.

O que vem junto

Peças prontas para colar e validadores que rodam.

Cinco skills de domínio por trás dos comandos de etapa: power-platform, powerapps-canvas, power-automate, sql-procedures e dataverse.

25

Componentes Canvas

YAML pronto para colar, com as variáveis que cada um espera no OnStart.

  • menu lateral (fixo, recolhível ou gaveta), menu no topo, tela inicial com cartões
  • galeria em tabela, ordenação, paginação por cursor, card de KPI
  • modais, overlay de carregamento, toast, estado vazio, painel sem acesso
34

Blocos de Power Automate

JSON de área de transferência mais notas, com a ordem de montagem de cada tipo de fluxo.

  • identificar e autorizar quem chama, escopo por unidade
  • gravar via stored procedure, traduzir código e responder
  • upsert $batch no Dataverse, exportação CSV, log de execução
✓

Validadores executáveis

Python, só biblioteca padrão. ✅ exige evidência: comando, saída e data.

  • validar-telas.py para telas
  • verificar-fluxo.py para fluxos
  • lint-procedure.py, verificar-prototipo.py
Uma trilha de dados por projeto: SQL Server ou Dataverse.
O nome real vence. Fórmulas e fluxos usam os nomes lidos do ambiente, nunca os do plano.
Escrita sempre passa por um fluxo, com resposta de 4 campos e .Run() dentro de IfError.
O fluxo lê a identidade de quem chama do próprio contexto e autoriza cada ação.
Nenhum literal de ambiente nas entregas: variáveis de ambiente e connection references no lugar.
Gerador nunca sobrescreve o que foi colado. O que é gerado vai para dist/.

Instalar

Dois comandos, depois /pp:novo.

Dentro do Claude Code, adicione o marketplace e instale o plugin. Digite /pp: para ver os comandos de etapa; se não aparecerem numa sessão que já estava aberta, reinicie o Claude Code.

Dentro do Claude Code
/plugin marketplace add <owner>/power-platform-skills
/plugin install pp@power-platform-kit
Ou pelo terminal
claude plugin marketplace add <owner>/power-platform-skills
claude plugin install pp@power-platform-kit
Seu primeiro app
/pp:novo um app para acompanhar pedidos entre as unidades

Para atualizar depois: claude plugin marketplace update power-platform-kit e, em seguida, claude plugin update pp.
