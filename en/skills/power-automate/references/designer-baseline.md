# Designer baseline: what it returns and what a generator must reproduce

A flow generated by a script and pasted into the designer comes back **different**. Every
difference measured between what the script emitted and what the designer returned is a rule.
Thirteen were measured (R1-R13); the generic ones and the reasons are kept here. What belongs to a
project (procedure names, real connection references, `CONFIG` values) stays in each project's
baseline. [verified: reference project]

## 1. Method

1. Paste the generated flow into the designer, save it, copy the scope back.
2. Compare the returned JSON with the emitted one, rule by rule, **with a count per flow**.
3. Every systematic difference becomes a rule; every rule goes **into the generator's source**
   ([generator-and-baseline.md](generator-and-baseline.md)), not into a permanent post-processor.
4. The file the designer returned is the **baseline**: immutable. When it diverges from any
   document or generator, the baseline wins -- it is the only environment evidence that exists.

## 2. The rules

"Blocks" = the flow pastes but fails at run time, or does not even save. "Normalizes" = the
designer accepts it without the rule, but the file stops being comparable with what the designer
returns and the next diff turns into noise.

| Rule | Content | Effect | Why |
|---|---|---|---|
| **R1** | `allConnectionData` with **one entry per `OpenApiConnection` action**, with the id of the connection reference **of the target environment** | **blocks** | Without the entry the paste does not rebind the connection. Checked by F017 |
| **R2** | No `"authentication": "@parameters('$authentication')"` in `inputs` | normalizes | The designer does not return it |
| **R3** | Empty `runAfter` is **omitted** (except on the root scope, which keeps `{}`) | normalizes | Same |
| **R4** | SQL action with `server` and `database` = the literal `"default"` | **blocks** | The expression form (`@{outputs('CONFIG')...}`) was refused; the real server comes from the connection reference. `CONFIG` loses those keys |
| **R5** | A connector parameter is a **bare** `@expr`, never `@{expr}` | **blocks** | `@{}` forces text: an `INT` column parameter receives a string. A text field inside `Response.body` stays interpolated. Checked by F018 |
| **R6** | `Response.inputs` in the order `schema, statusCode, body` and `schema.additionalProperties = {}` | normalizes | Returned form |
| **R7** | Action key order: `type, [kind], inputs\|expression, [actions/else/cases/default], runAfter, metadata` | normalizes | `runAfter` **before** `metadata` |
| **R8** | Every `If` with an explicit `else: {"actions": {}}` | normalizes | Returned form |
| **R9** | The database object name (procedure) is the environment's **AS-BUILT** one, not the document's | **blocks** | Generic mechanism: a `procedures_as_built` data block + a mapping checked against `sys.procedures`; never invent a name. The values belong to the project |
| **R10** | `take(x, N)` in place of `substring(x, 0, min(length(x), N))` | optional | Reduces size and leaves headroom against the 8,192 limit; `take()` is already safe for text shorter than N |
| **R11** | `CONFIG` with real values, not `SUBSTITUIR-*` | project | Values belong to the project; the key must not be left unread |
| **R12** | `int(coalesce(string(X),'0'))` blows up at run time: `string(null)` is `''` | **blocks (runtime)** | See [wdl-expression-pitfalls.md](wdl-expression-pitfalls.md). F012 |
| **R13** | `outputs()` of `Select`/`Query` returns the envelope; use `body()` | **blocks (runtime)** | Same. F011 |

Real tally when measuring several flows against the baseline: R1, R4, R5 and R9 blocked execution;
R2, R3, R6, R7 and R8 were only normalization.

## 3. What the verifier covers and what it does not

| Rule | `verificar-fluxo.py` |
|---|---|
| R1 | F017 |
| R5 | F018 |
| R12 | F012 |
| R13 | F011 |
| R2, R3, R6, R7, R8, R10 | **left out on purpose**: they do not block execution; flagging them would add noise to every flow that came from the designer |
| R4 | out: depends on the connection type (with gateway/default connection); record it in the project baseline |
| R9, R11 | out: they depend on the environment; they live in the project's `AS-BUILT-NAMES` (skill `dataverse`/`sql-procedures`) |

Gates of the "WDL/Logic Apps" family that the verifier also covers because no business rule is
needed: duplicate name (F004), orphan `runAfter` (F005), reference to a nonexistent action (F006),
`items()` outside the `Foreach` (F007), case x action (F008), `Catch` without `Skipped` (F009),
`Response` without the 4 fields (F010), `Response` without `Terminate` (F015), constant condition
(F016), expression above 8,192 characters (F013).

## 4. How to become a new rule

A defect that only shows up on paste or on the first run **comes back** if it is fixed at an
isolated spot. The three `string(null)` leaks (in `substring`, in `data_curta` and in `int()`)
were each fixed in one place and reappeared. So:

1. Fix **the whole file**, not just the occurrence that blew up (regex sweep).
2. Write the gate (a function that flags the pattern) and the fixture that fails (P4 in
   [default-decisions.md](../../power-platform/references/default-decisions.md)).
3. If the pattern belongs to the "runtime pitfall" family, add it to
   [wdl-expression-pitfalls.md](wdl-expression-pitfalls.md) and to the verifier.
